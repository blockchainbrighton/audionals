# BVST (Bitcoin Virtual Studio Technology) Reference Implementation

## Project Overview
This repository contains a reference implementation of the **BVST Ordinals Standard (RFC-002)**, a plugin architecture designed for "on-chain" Digital Audio Workstations (DAWs).

The core philosophy is to create a professional music studio where the entire asset library measures in Kilobytes, ensuring it survives on the Bitcoin blockchain forever. Plugins are modular, utilizing **WebAssembly (WASM)** for DSP logic, **HTML/JS** for UI, and **JSON** for the manifest.

### The "Tri-Part Inscription" Architecture
A BVST plugin consists of three distinct components:
1.  **The Brain (Kernel):** DSP logic written in Rust and compiled to WebAssembly (`.wasm`). It runs in an `AudioWorklet` for high-performance, glitch-free audio.
2.  **The Face (Interface):** A visual interface written in HTML/JS (`gui.html`). It communicates with the kernel via the host.
3.  **The Map (Manifest):** A JSON file (`manifest.json`) that links the Kernel and Interface, defining parameters and assets.

## Directory Structure

*   **`bvst_engine/`**: The Rust crate containing the DSP logic.
    *   `src/lib.rs`: The core synthesizer implementation (`BvstSynth`).
    *   `Cargo.toml`: Project dependencies (requires `wasm-bindgen`).
*   **`bvst_engine_bg.wasm`**: The compiled WebAssembly binary (output of the build process).
*   **`bvst_engine.js`**: The JavaScript bindings generated by `wasm-pack`.
*   **`processor.js`**: The `AudioWorkletProcessor` "glue" script. It loads the WASM module and bridges the Web Audio API with the Rust engine.
*   **`gui.html`**: The plugin's user interface (loaded into an iframe by the host).
*   **`manifest.json`**: The plugin definition file.
*   **`index.html`**: A minimal "Host" (DAW) implementation to test the plugin.
*   **`server.py`**: A simple Python HTTP server to serve the files with correct MIME types (essential for WASM/Worklets).
*   **`Standard.md`**: The BVST specification document.

## Development & Usage

### Prerequisites
*   **Rust:** Install via `rustup`.
*   **wasm-pack:** Install via `cargo install wasm-pack`.
*   **Python 3:** For the local development server.

### Building the Audio Engine
To compile the Rust code into WebAssembly:

```bash
cd bvst_engine
wasm-pack build --target web --out-dir .. --no-typescript
```
*Note: This command outputs the `.wasm` and `.js` binding files directly to the project root to match the `manifest.json` structure.*

### Running the Project
1.  Start the local server:
    ```bash
    python3 server.py
    ```
2.  Open your browser to `http://localhost:8000`.
3.  Click **START AUDIO ENGINE**.
4.  The "Satoshi Sawtooth" synth will start running. Adjust the knobs in the UI (if implemented) or via the console to hear changes.

### Key Workflows
*   **DSP Logic:** Edit `bvst_engine/src/lib.rs` to change how the sound is generated.
*   **UI:** Edit `gui.html` to change the visuals.
*   **Glue:** Edit `processor.js` if you need to change how parameters are passed between the UI and the WASM kernel.

## Conventions
*   **Efficiency:** Code size matters. Avoid heavy dependencies in Rust. The goal is to keep the WASM kernel under 20KB.
*   **No DOM in Kernel:** The WASM code runs in an `AudioWorklet` thread and cannot access the DOM. All communication must go through the `AudioWorkletProcessor` messaging system.
*   **Sample Rate:** The standard uses 48kHz.
